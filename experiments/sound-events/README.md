# 键盘 / 风声事件判断（端侧规则原型）

回答的问题：**CoreS3 能不能把"敲键盘""风声"和"说话/安静"分开？**
结论：**能，用现有 24 段环境谱就够了**。2026-10-19 两段真机采集上：

| 指标 | 数值 |
|---|---|
| keyboard / wind 召回 | **83.7%**（keyboard 78% / wind 90%） |
| 安静 / 说话 误报事件 | **0.0%**（359 个说话窗 + 96 个安静窗，没有一窗被判成键盘/风） |
| 留出（每段后 40% 时间，未参与调参） | keyboard 28% / wind 85% / 误报 0% |
| **真机（v5b 固件）复测** | 键盘段 79% 帧报 keyboard；风段 **0 帧误报 keyboard**；敲桌报 artifact |

**留出里 keyboard 掉到 28% 的原因已经查清**：第二个键盘段（72.5–84.9 s）正好被一次撞击打断
（75.2–79.1 s 撞击 + 2 s 重攒窗），且那一段击键明显更轻、斜率更陡；加入"键盘斜率不能太陡"
的门（见下）之后，这一段被牺牲得更多。第一个键盘段（22.6–39.9 s）是 **94%**。这不是规则
"只在调参段有效"，而是输入本身变弱；但也不能据此说跨条件泛化没问题。

## 为什么是规则，不是直接重训 9 类模型

1. 9 类模型（`listening_model.h`）**没有 keyboard 类**，且 `wind` 类是合成语料训的——真机
   实测：键盘 87%、吹风 89% 都判成 `other`（见 `记录/键盘风声/20261019-141545/report.md`）。
2. 重训需要成规模的**真机标注数据**，现在只有两段。先验证"特征可分"再决定是否投入训练。
3. 事件判断只需要回答"此刻有没有键盘/风"，不需要 9 类语义；1 s 窗规则可以在主机上跑，
   也可以逐行搬进固件（`main/sound_event.hpp`），没有新依赖。

## 数据

| 采集 | 内容 | 文件 |
|---|---|---|
| 20261019-141545 | 安静 10 s / 敲键盘 20 s / 吹风 20 s / 再敲 15 s / 再吹 15 s（含 3 次撞击） | `记录/键盘风声/20261019-141545/live.csv` |
| 20261019-142748-speech | 安静 8 s / **说话 40 s** | `记录/键盘风声/20261019-142748-speech/live.csv` |

- 麦克风：CoreS3 板载 ES7210（产品麦克风，不是 Mac 麦）。
- 采样：设备每 100 ms 输出一行 24 段 dBFS；采集工具 `tools/live_band_capture.py` 轮询在位
  上位机的 `/api/snapshot`，不占串口。
- 剔除：每段开头 2.5 s（提示音/动作起始跳变）；**撞击帧**（`context_valid=false`）不参与
  训练与评估。撞击的峰值宽带电平是 −13 ~ −16 dBFS，比所有有效声音（最高 −20.1）都响。
- 标签来自分段协议（人给的），不是模型自标。

## 方法

### 15 维窗特征（1 s = 10 帧）

全部由 24 段 dBFS 的初等函数算出，**不引入新 DSP**，C++ 可逐行照搬：

| 特征 | 含义 |
|---|---|
| `d_lo` / `d_mid` / `d_hi` | 低 / 中 / 高频段相对噪声地板的抬升（dB） |
| `mid_lo` / `hi_mid` | 上面三者的差，描述频谱形状 |
| `cent` | 频谱质心（Hz）——键盘咔哒是宽带瞬态，质心明显更高 |
| `flat` | 频谱平坦度（几何/算术均值） |
| `vr` | 语音带（300–4000 Hz）能量占比 |
| `vocal_peak` | 语音带内最大单频段占比——**说话最集中的特征** |
| `slope` | 24 段 dB 对频段序号的最小二乘斜率——风最陡 |
| `low_share` | 低频段（<500 Hz）能量占比——键盘最低（咔哒是宽带） |
| `std_lo` / `range_lo` | 低频段包络在 1 s 内的标准差 / 极差——阵风起伏 |
| `std_mid` | 中频段包络的 1 s 标准差——击键瞬态 |
| `level_rel` | 宽带电平相对噪声地板的抬升 |

噪声地板用**向下快、向上慢**的跟踪器（0.25 / 0.002），不用"安静段中位数"：固件开机时
不知道哪一段安静，用中位数会让训练口径和推理口径错位。金标准由
`export_golden.py` 从真机窗口导出，C++ 单测逐维比对。

### 规则 + 状态机

```
keyboard  low_share < 0.55 且 std_mid > 4 dB 且 cent > 600 Hz
          且（slope > -1.35 或 cent > 800 Hz）
wind      slope < -1.45 且 vocal_peak < 0.45 且 d_lo > 16 dB 且 range_lo > 14 dB
speech    vocal_peak > 0.45
quiet     其余
```

判定后过状态机：keyboard 保持 0.8 s、wind 保持 2.0 s、speech 保持 0.8 s；keyboard 优先，
不会被风覆盖。**撞击**是前置门控：`mic_valid=false` 时清空 1 s 窗并报 `artifact`，
绝不把撞击瞬态喂给键盘规则（两者时域上都像冲击）。

### 为什么这些阈值"物理上说得通"

| 声音 | 中位特征 | 与安静的差 |
|---|---|---|
| 键盘 | 中频段 −66.6 dBFS、质心 **932 Hz**、低频占比低 | 中频 **+7.1 dB** |
| 吹风 | 低频段 −55.5 dBFS、质心 442 Hz、斜率 −1.6 dB/段 | 低频 **+7.3 dB**（强吹 +10） |
| 说话 | 语音带峰值集中度 **0.52**（键盘/风/安静 0.34–0.37） | — |
| 安静 | 质心 449 Hz、低中频均低 | — |

## 结果

逐窗混淆（行=真值，状态机平滑后；总共 964 个窗，含 132 个撞击/无效窗已排除）：

```
               quiet    speech  keyboard      wind    n
quiet             76        20         0         0     96
speech            56       303         0         0    359
keyboard          42         0       194        14    250
wind              24         0         3       232    259
```

- 键盘误判成风的 14 窗、风误判成键盘的 3 窗都在"击键很轻/阵风刚起"的边界上。
- **加斜率门的理由**：真机 v5 复测（2026-10-19）里，风段有 25% 帧被报成 keyboard——阵风
  也有大的 `std_mid`，但它的频谱斜率更陡（≤ −1.45）。加 `slope > -1.35`（质心 > 800 Hz 时
  豁免）后，真机风段**0 帧**误报 keyboard，键盘召回不变（115/126）。
- 说话没有一窗被判成键盘/风；但"是否判成说话"只有 84%——规则对轻声/远场说话会退回
  `quiet`。事件判断不依赖 speech 类，这条不影响产品方向。

## 局限（这些数字不能怎么用）

- **两个采集、一个键盘、一个房间、一个人**；没有换键盘、距离、风扇、自然风、电视/音乐
  的对照。阈值是这两段上调出来的，**不是跨条件泛化证据**。
- "风声"是人工吹气（20–30 cm），强吹还伴随近场饱和；不代表真实风噪或耳机风噪。
- 说话样本是操作者读/讲 40 s，不是多人、多语言、多距离。
- 规则只有四类；没有"其他瞬态"（关门、敲桌子未削波、杯子碰桌）的负样本。
- 设备端尚未真机验证（截至本文件写入，固件已编译通过、主机单测 26 条通过，待刷机）。

## 真机复测（2026-10-19，v5 / v5b 固件）

固件刷入后，用同一套采集脚本做了两次现场复测：

| 版本 | 键盘段 | 风段 | 敲桌段 | 备注 |
|---|---|---|---|---|
| v5（加斜率门前） | 146/180 帧 keyboard（81%） | 89/160 wind（56%），**32 帧误报 keyboard（20%）** | 64% 帧 quiet，20 帧 artifact | 阵风被当键盘 |
| v5b（加斜率门后） | 119/150 帧 keyboard（79%），31 帧 quiet（击键间隙） | 74/140 wind（53%），**0 帧误报 keyboard** | 31 帧 invalid（削波），10 帧 artifact，5 帧 keyboard | 风误报修掉 |

两次都观察到的现象：

- 键盘是**连续可判**的（v5 从 21 s 到 35 s 连续 15 秒），不是零星闪烁。
- 敲桌**不削波时**通常落到 `quiet`，削波时才报 `artifact`——这正是设计意图：宁可漏报
  （quiet），也不要把撞击判成键盘。v5b 敲桌段只有 5/60 帧报 keyboard。
- 环境四分类在房间本底下**全程 `VOICE` / `conversation=LIKELY`**（媒体一直 60%），
  与第 38 项既有缺陷一致；事件判断不依赖它。
- 风段前几秒判 quiet 是因为吹气还没起来/较弱；强吹开始后才连续判 wind。

**这些是现场行为验证，不是准确率测量**：每段只有 1 次、没有重复，且"静置"段里似乎混有
真实击键（特征与键盘段一致）。跨键盘/距离/房间的准确率仍然没有数据。

## 混合场景（说话+风）的离线验证（2026-10-19）

没有现场混合环境，做了两层替代验证，结论只用于**机制判断**，不作准确率证据：

1. **数字混音（16 kHz 音频按 SNR 叠加，过官方 YAMNet）**：

| SNR | 干净说话 | −5 dB | 0 dB | +5 dB | +10 dB |
|---|---|---|---|---|---|
| Speech 帧命中率（>0.5） | 79% | 20% | 34% | 44% | 51% |

风对说话有明显掩蔽；但 Speech 峰值仍可到 0.96–0.98，说明"完全检不到"不成立，是**召回下降**。

2. **设备 24 段上的幂域混音**（把纯风帧与纯说话帧的频段功率相加后回放）：

| 输入 | wind 规则 | speech 规则 | 两者同时 |
|---|---|---|---|
| 纯风 | 35% | 7% | 0% |
| 纯说话 | 0% | 26% | 0% |
| 混合 | 15% | 18% | **0%** |

混合把两边的特征都稀释（d_lo 17.4/10.6 → 13.5，slope −1.69/−1.07 → −1.50），
单输出类别永远只能二选一——这直接支撑 D21 的"两路正交输出 + 双头学生"设计。

3. **外放 surrogate（Mac 播风声 + TTS）失败**：Mac 当时静音，且扬声器回放的"风"在声学上
   不像真风（教师 wind_mic≈0、设备 wind 规则 0–4%），不能作为混合数据。已恢复静音。

**结论**：混合场景的"架构"可以现在定（两路独立），但"准确率/阈值"必须等真实混合数据；
合成数据不能用于 D18 准入。
