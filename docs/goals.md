# 这个 demo 现在到底要什么（目标口径，2026-10-19 用户确认）

> 一句话：**S3 负责感知与决策，Mac 负责执行；行为目标是"对话发生时把音乐让开、让人声进来"，
> 不是给所有声音加增益。** 小模型只在这条链路里做它们擅长的事，没通过验收就不进决策。

## 1. 总目标

- 设备：M5Stack CoreS3（ESP32-S3，无 NPU），板载双麦，蓝牙不可用；音频通过 USB 串口到 Mac。
- 耳机：AirPods（Mac 侧控制）；**不做降噪**，本机动作只有：媒体音量下压/恢复、歌曲 EQ
  建议、AirPods 聆听模式（通透）切换。
- 产品意图：预判式对话感知——**对方一开口就先让位**，不是等自己说完才反应。
- 硬约束：端侧 ≤2 ms/帧、≤64 KB RAM、≤256 KB 权重、额外延迟 ≤20 ms；事件/模型更新必须
  经过验收与版本化，不现场自学。

## 2. 调音/行为目标

| 场景 | 目标动作 | 验收 |
|---|---|---|
| 附近有人开口（对话开始） | 预下压媒体到 70% | 第一拍就动，≤1 帧检测 |
| 对话确认 | 媒体压到 60%，EQ 全平，ambient_open 意图 true | 真机 media=60、mode=FLAT、ambient=true |
| 对话中 | 保持 2.5 s，句间不抬回 | 短促声不触发切换 |
| 对话结束 | 2.5 s 后媒体恢复、关闭环境声 | 恢复平滑 |
| 安静 / 环境噪声 | 环境噪声：歌曲 EQ 建议（≤4 dB/段，播放器深度×4，总上限 +10 dB）；安静 flat | 面板可见、可听 |
| 风 | 低频段（0–4，70–451 Hz）抬升压到 1/4；中高频不动 | 风 EQ 听感 A/B（待真实风） |
| 高噪声（> -30 dBFS） | 安全保持，禁止正增益 | 单测 |
| 麦克风故障/撞击 | 复位对话、关环境声、恢复媒体；artifact 清窗 | 单测 + 协议合法 |
| 自己哼哼/独白 | **不压** | 未实现：单麦无法区分自身哼鸣与他人说话，待用户选路线（D25） |
| 键盘/咳嗽/撞桌 | 不进入对话、不当成人声 | 事件规则 + artifact 门控 |

**增益语义**：`speech_gain_db` / `external_voice_gain_db` 是意图遥测；真实"外部人声增益"
没有执行端。**默认不把歌曲 EQ 当人声增益**（D25）。

## 3. 小模型的分工与赋能目标

| 模型 | 输入/窗 | 输出 | 目标 | 当前状态 |
|---|---|---|---|---|
| 声音事件规则（`sound_event.hpp`） | 24 段 ×1 s，15 维 | keyboard/wind/speech/artifact | 让设备知道"键盘/风/撞击/人声"；artifact 防止撞桌误判键盘；wind 驱动风 EQ | ✅ 上机；事件耗时 p50 269 µs；撞桌协议 bug 已修 |
| 情境模型（`listening_model.h`） | 92 维 ×2 s | 9 类场景 | 面板展示场景（near_voice/music/wind…），只遥测 | ✅ 上机只显示，不决策 |
| 说话 gate 学生（`speech_gate_model.h`） | 92 维 ×2 s | 说话/非说话 2 类（2.3k 参数） | **替代四判据做"有人说话"决策**；D19 验收：多条件留出段 speech 召回不降、非语音误报 <10% | 🟡 只遥测；跨会话未过线（误报 3–44%），等真实多说话人/距离数据 |
| 教师（YAMNet/AST，Mac） | 0.96 s / 10.24 s | AudioSet 标签 | 自动标说话/键盘；风/敲桌弱，不用它标风/敲桌 | ✅ 离线工具链；数据入库 |
| 更新飞轮 | 上位机校验 → incident → 离线重训 → 影子 → 验收 → 发布/回滚 | — | 不在设备上自学；错误先用确定性修复（D22） | ✅ 流程已定；host 协议校验已在抓错 |

## 4. 验收与现状

- 已验证：对话下压 + 环境声（AirPods 通透）真机可跑；事件耗时 269 µs、感知 193 µs、
  speech gate 208 µs；artifact 协议合法；风 EQ 单测；C++ 11 套件、上位机 52 组 7559 条、
  渲染校验、CI 全绿。
- 未过验收：① 说话 gate 的 D19 跨会话误报；② 风 EQ 真实风听感；③ "自己哼哼不压"
  （需自身语音区分）；④ 真实"说话+风"混合场景。
- 下一步最缺的数据：真实多说话人/多距离、键盘、真实风、说话+风；以及 10–20 s 的用户
  哼哼/独白（用来做哼鸣拒绝器）。
