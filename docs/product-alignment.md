# Demo 产品口径（唯一基准）

最后更新：2026-10-21（收尾；耳机 TWS/OWS 双设备兼容，D35/D36）

## 一句话

用 **CoreS3 模拟 AI OWS 耳机仓**：S3 常开感知环境并做端侧决策，Mac 播放两首本地歌曲并执行
EQ / 媒体下压 / 环境声中继，耳机只负责播放最终输出（自动识别 OWS 耳夹 Xiaomi 耳夹式耳机
与 TWS 对照 AirPods Pro，D35/D36）。本 demo 验证的是**预判式对话
感知**（附近有人开口先让位）、歌曲 EQ、现实声音中继的延迟边界与安全退出策略。

## Demo 分工

```text
CoreS3（耳机仓）
  麦克风环境采集 → 24 段环境谱 / 人声判据 / 声音事件 → 端侧策略（预判式对话感知，D16）
    ├─ 媒体下压/恢复（Mac 执行）
    ├─ SONG_EQ：24 段歌曲 EQ 建议（Mac 执行）
    ├─ EXTERNAL_VOICE_INTENT：背景人声时的歌曲掩蔽（D41，不是人声增强）
    ├─ SAFETY_HOLD：高噪声禁止正增益
    └─ ambient_open 意图（协议 v4）
                                                      ↓ USB
Mac（播放器与原型执行器）
  tools/player（Swift，实时 24 段 EQ）+ tools/host（面板/状态/回控/声纹）
  环境声执行端：relay（S3 麦克风→耳机）或 airpods（仅 TWS 对照）；默认 off（D30）
                                                      ↓ 蓝牙音频
当前耳机（自动识别：Xiaomi 耳夹 / AirPods Pro）
  播放 Mac 最终输出
```

耳机（OWS 耳夹与 AirPods Pro 同样）不开放双耳原始麦克风、声学 DOA、通透 DSP 或现实人声
增益接口；本 demo 用 S3 麦克风代表耳机仓感知，不能写成"已经使用耳机双耳麦克风"或
"已完成目标人声增强"。

## 行为口径（2026-10-21）

| 场景 | 期望动作 | 执行端 |
|---|---|---|
| 附近有人持续开口（预判，D40/D49） | **事件层 speech 证据**（D49）连续 0.5 s 后媒体预下压 70%；0.8 s 后压到 60%，并置 `ambient_open=true`；首响比旧口径慢约 1 s（事件窗） | S3 决策；Mac 下压 |
| 声纹判定 self | **不压、不抬、不开环境声**（D28/D31 self-veto，实验性） | Mac WavLM → S3 |
| 声纹判定 other | 按 D16 预判逻辑正常动作 | 同上 |
| 背景/别人说话但未成对话 | **掩蔽**：事件层 speech（D49）+ 全频段 +1 dB、1–4 kHz 抬到单段上限（`EXTERNAL_VOICE_INTENT`，D41）；不压媒体、不开环境声 | Mac 执行 |
| 稳态环境噪声 | `SONG_EQ` 24 段**有符号**内容曲线（D39）+ **普通噪声掩蔽**：全频段 +0.3 dB、1.6–4 kHz +1.0 dB（随电平 -54→-34 缩放；D48） | Mac 执行 |
| 敲键盘 | **特殊掩蔽**：全频段 +0.5 dB、键盘足迹段 1.0–3.4 kHz +1.5 dB（D48，深度独立慢平滑 400 ms/1.2 s）；不压媒体、不开环境声、不进对话 | Mac 执行 |
| 风 | 低频抬升压到 1/4（D21） | Mac 执行 |
| 高噪声（> -30 dBFS） | `SAFETY_HOLD`，禁止正增益 | S3 决策 |
| 自己哼唱/独白 | 目标"不压"；当前由实验性 self-veto 部分覆盖，**未验收**（D25/D31） | — |

**增益语义**：`speech_gain_db` / `external_voice_gain_db` 是意图遥测；真实"外部人声增益"
没有执行端（D25）。**背景人声/键盘/稳态噪声场景的实际动作都是"掩蔽"（D41/D48）**：用歌曲
能量盖住噪声，不是把对方的声音放大，也不是降噪/隔音。不得把"抬歌曲中频"或用 S3 中继写成
"对方声音已增强"，也不得写成"降噪"。

**感知点口径（D49）**：S3 = 耳机仓，感知点在人身边（桌面靠人/领口/口袋）。贴键盘 =
过度测量；贴耳 = 贴着自己在放的喇叭（OWS 物理漏音，无播放参考信号无法在耳边区分）。
演示验收几何按"耳机仓在人身边"写。

## 环境声执行

- `ambient_open` 是**意图**，不是回执；执行结果、失败原因、放行/丢弃包数必须在面板分开显示。
- `--ambient-executor` 可选 `off` / `relay` / `airpods`；**真机默认 `off`**（D30）。
- `airpods` 只对 TWS 有效（AX 切聆听模式）；OWS 耳夹物理开放、没有聆听模式，`ambient_open`
  在 OWS 上退为意图/遥测 + 中继门控（D35）。
- **执行门（D42；2026-10-26 晚触发源收窄）**：`--ambient-gate voice|llm` 下，只有**新鲜的
  LLM 语义确认**（`dialogue=yes`）才真正执行 `ambient_open`；S3 意图、voiceprint `self`、
  声纹双向交替都**不再开环境声**（现场实测会误开：固件 event/vl 把近场语音错判成
  keyboard/wind、单人连续说话被声纹切成 self+other 假交替）。`self`/交替证据仍驱动**媒体
  下压门栓**（`voice` 门比 `llm` 门更快让位）；背景人声只显示意图、不执行。代价：环境声
  开门延迟 = LLM 往返约 5–10 s（准确优先于速度）。门只拦执行，不拦 S3 的媒体下压与 EQ。
- **迟到否决回写快路径（D50）**：host 把新鲜否决（LLM `dialogue=no` 或本地"无有效语音"）
  经 `dialog no [ttl_ms]` 回写 S3（TTL 20 s、每 5 s 续期）；S3 在 TTL 内释放对话态
  （媒体回 100%、`ambient_open` 意图关闭），背景人声回落为掩蔽。
  它只否决策略里的"是不是对话"，不改噪声/EQ；撤销/过期/退出时 host 发 `dialog yes`，
  且 S3 自己 fail-open（TTL 到点恢复 D16 预判，不依赖 host）。
- 没有 Mac 执行回执前，协议固定报 `execution: decision_only`。

## 延迟口径（已实测）

- 端侧：控制节拍 100 ms（设备自报采集 100.03 ms）、24 段分析 7.02 ms、决策 0.06 ms。
- 上位机：主机侧帧到达间隔 p50 100.00 ms（自检，不是设备节拍）。
- S3 麦克风 → 耳机（relay 拓扑）：**AirPods Pro 约 211–231 ms**（排队 40–60 + 蓝牙驱动侧
  170.7 ms）；**Xiaomi 耳夹约 385–405 ms**（排队 40–60 + 驱动侧 **324.8 ms**，2026-10-21
  实测，44.1 kHz），另外设备侧打包约 20 ms。两组都是该拓扑的**物理下限**，只有换拓扑
  （LE Audio / 混音在出声设备上，D2/D3）才可能明显降低。
- 不能证明耳机已播放参数；这条链路没有回执。

## 上下文与个人历史

目标策略是"环境声音 + 当前时间/活动 + 个人历史 + 用户纠正 → 怎样调、何时调、何时退出"。
当前固件只有环境声音判据与短时对话状态机；**用户记忆（memo）已落盘并作为慢层弱先验注入
LLM（D38）**，但"记忆进入执行"仍是影子阶段（未验收）。时钟日程、ABC 身份识别、车声分类
和用户纠正学习仍未实现；缺失项必须显示为待实现，不能由 UI 文案代替。

## 完成判据

1. 两首本地歌曲默认暂停，用户手动播放；Mac 播放器能应用到实时 EQ。
2. S3 每帧发送环境谱、模式、对话状态、EQ 建议、`ambient_open` 意图、声纹遥测与置信度。
3. Mac 回报当前输出设备，S3 第二页显示命中的耳机短名（默认 `Xiaomi OWS` / `AirPods Pro`，
   `--earphone MATCH=LABEL` 可配）与真实路由状态；未识别显示 `Earphone` + 未连接。
4. 对话成立时媒体下压到 60%、EQ 平直；结束后 2.5 s 恢复。
5. 环境声默认 off；显式 relay 时执行结果如实上报，失败不得写成成功；airpods 仅 TWS 对照可用。
6. UI 始终区分"决策已产生 / Mac 已执行 / 耳机已播放"三种状态。
