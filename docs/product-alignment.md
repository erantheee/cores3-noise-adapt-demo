# Demo 产品口径（唯一基准）

最后更新：2026-10-21（收尾）

## 一句话

用 **CoreS3 模拟 AI OWS 耳机仓**：S3 常开感知环境并做端侧决策，Mac 播放两首本地歌曲并执行
EQ / 媒体下压 / 环境声中继，AirPods Pro 只负责播放最终输出。本 demo 验证的是**预判式对话
感知**（附近有人开口先让位）、歌曲 EQ、现实声音中继的延迟边界与安全退出策略。

## Demo 分工

```text
CoreS3（耳机仓）
  麦克风环境采集 → 24 段环境谱 / 人声判据 / 声音事件 → 端侧策略（预判式对话感知，D16）
    ├─ 媒体下压/恢复（Mac 执行）
    ├─ SONG_EQ：24 段歌曲 EQ 建议（Mac 执行）
    ├─ EXTERNAL_VOICE_INTENT：背景/别人说话时的中频 EQ 代理（D26）
    ├─ SAFETY_HOLD：高噪声禁止正增益
    └─ ambient_open 意图（协议 v4）
                                                      ↓ USB
Mac（播放器与原型执行器）
  tools/player（Swift，实时 24 段 EQ）+ tools/host（面板/状态/回控/声纹）
  环境声执行端：relay（S3 麦克风→耳机）或 airpods（通透模式）；默认 off（D30）
                                                      ↓ 蓝牙音频
AirPods Pro（本次耳机）
  播放 Mac 最终输出
```

AirPods Pro 不开放双耳原始麦克风、声学 DOA、通透 DSP 或现实人声增益接口；本 demo 用 S3
麦克风代表耳机仓感知，不能写成"已经使用 AirPods 双耳麦克风"或"已完成目标人声增强"。

## 行为口径（2026-10-21）

| 场景 | 期望动作 | 执行端 |
|---|---|---|
| 附近有人开口（预判） | 第一拍媒体预下压 70%；证据持续 200 ms 后压到 60%，并置 `ambient_open=true` | S3 决策；Mac 下压 |
| 声纹判定 self | **不压、不抬、不开环境声**（D28/D31 self-veto，实验性） | Mac WavLM → S3 |
| 声纹判定 other | 按 D16 预判逻辑正常动作 | 同上 |
| 背景/别人说话但未成对话 | 抬 8–16 段中频（`EXTERNAL_VOICE_INTENT`，D26） | Mac 执行 |
| 稳态环境噪声 | `SONG_EQ` 24 段建议（≤4 dB/段；播放器深度倍率后总上限 +10 dB） | Mac 执行 |
| 风 | 低频抬升压到 1/4（D21） | Mac 执行 |
| 高噪声（> -30 dBFS） | `SAFETY_HOLD`，禁止正增益 | S3 决策 |
| 自己哼唱/独白 | 目标"不压"；当前由实验性 self-veto 部分覆盖，**未验收**（D25/D31） | — |

**增益语义**：`speech_gain_db` / `external_voice_gain_db` 是意图遥测；真实"外部人声增益"
没有执行端，默认不把歌曲 EQ 当人声增益（D25）。不得把"抬歌曲中频"或用 S3 中继写成
"对方声音已增强"。

## 环境声执行

- `ambient_open` 是**意图**，不是回执；执行结果、失败原因、放行/丢弃包数必须在面板分开显示。
- `--ambient-executor` 可选 `off` / `relay` / `airpods`；**真机默认 `off`**（D30）。
- 没有 Mac 执行回执前，协议固定报 `execution: decision_only`。

## 延迟口径（已实测）

- 端侧：控制节拍 100 ms（设备自报采集 100.03 ms）、24 段分析 7.02 ms、决策 0.06 ms。
- 上位机：主机侧帧到达间隔 p50 100.00 ms（自检，不是设备节拍）。
- S3 麦克风 → 耳机（relay 拓扑）：进播放端到耳机出声约 **211–231 ms**（播放端排队 40–60 ms
  + 蓝牙驱动侧 170.7 ms），设备侧打包约 20 ms。这是该拓扑的**物理下限**，只有换拓扑
  （LE Audio / 混音在出声设备上，D2/D3）才可能明显降低。
- 不能证明 AirPods 已播放参数；这条链路没有回执。

## 曲库

当前 **两首**：`tools/player/tracks.json`（《渡口》、Sweet Child）。`path` 是录制机器的本地
绝对路径，换机器需改这里；加歌只需往 `tracks` 里加一项。

## 上下文与个人历史

目标策略是"环境声音 + 当前时间/活动 + 个人历史 + 用户纠正 → 怎样调、何时调、何时退出"。
当前固件只有环境声音判据与短时对话状态机；时钟日程、ABC 身份识别、车声分类和用户纠正学习
仍未实现。缺失项必须显示为待实现，不能由 UI 文案代替。

## 完成判据

1. 两首本地歌曲默认暂停，用户手动播放；Mac 播放器能应用到实时 EQ。
2. S3 每帧发送环境谱、模式、对话状态、EQ 建议、`ambient_open` 意图、声纹遥测与置信度。
3. Mac 回报当前输出设备，S3 第二页显示 `AirPods Pro` 与真实路由状态。
4. 对话成立时媒体下压到 60%、EQ 平直；结束后 2.5 s 恢复。
5. 环境声默认 off；显式 relay/airpods 时执行结果如实上报，失败不得写成成功。
6. UI 始终区分"决策已产生 / Mac 已执行 / AirPods 已播放"三种状态。
