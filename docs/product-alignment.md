# Demo 产品口径（唯一基准）

最后更新：2026-10-14

## 一句话

用 **CoreS3 模拟 AI OWS 耳机仓**，在本地持续感知环境并结合时间、个人历史和用户纠正做听音决策；
Mac 播放并处理三首固定本地歌曲，AirPods Pro 只负责播放最终输出，以验证综合调音、人声增益意图、
退出策略与端到端延迟是否真的改善体验。

## Demo 分工

```text
CoreS3（耳机仓）
  麦克风环境采集 → 24段环境谱/人声判据 → 端侧策略
                                            ├─ FLAT
                                            ├─ SONG_EQ
                                            ├─ EXTERNAL_VOICE_INTENT
                                            └─ SAFETY_HOLD
                                                      ↓ USB
Mac（播放器与原型执行器）
  三首本地歌曲 → 内容频谱 + S3环境谱 → 多段EQ/安全余量
                                                      ↓ 蓝牙音频
AirPods Pro（本次耳机）
  播放Mac最终输出
```

最终产品里，耳机自身麦克风与耳机仓共同收听，耳机仓是 AI 算力中心。当前 AirPods Pro 不向第三方
开放双耳原始麦克风、声学 DOA、通透 DSP 或现实人声增益接口，因此本次 Demo 用 S3 麦克风代表耳机仓
感知；不能把它写成“已经使用 AirPods 双耳麦克风”。

## 四种决策不能混写

| 决策 | 含义 | 当前执行状态 |
|---|---|---|
| `FLAT` | 安静或恢复阶段，不动作 | S3 已实现 |
| `SONG_EQ` | Mac 对三首本地歌曲做内容感知 EQ | S3 已输出意图；Mac 音频执行待接入 |
| `EXTERNAL_VOICE_INTENT` | 希望放大现实中对方说话，不是歌曲人声频段 | S3 已输出意图；AirPods 不支持直接执行，转发链路待测 |
| `SAFETY_HOLD` | 高噪声下禁止正增益，避免危险遮蔽 | S3 已实现保守规则；车声分类尚未实现 |

`EXTERNAL_VOICE_INTENT` 与 `SONG_EQ` 必须互斥。检测到现实人声时，不能把“现实人声增益”偷换成
抬高歌曲 1–4 kHz，也不能把降低歌曲音量写成“对方声音已增强”。

## 上下文与个人历史

目标策略是：

```text
环境声音 + 当前时间/活动 + 个人历史 + 用户纠正
  → 怎样调、何时调、何时退出或不动作
```

例如“8:10–8:30 通勤、可能过马路”只能作为个人历史先验；必须再有实时环境证据才能进入安全策略。
当前固件只有环境声音判据与短时对话形态启发式，尚未实现时钟日程、ABC 身份识别、车声分类和用户
纠正学习。缺失项必须显示为待实现，不能由 UI 文案代替。

## 延迟口径

- 已测：S3 采集节拍、24段分析和决策耗时。
- 待测：S3→Mac 传输、Mac EQ 应用、Mac→AirPods 播放。
- 风险最高：S3 麦克风语音→Mac→AirPods 的现实人声转发。它可能产生明显延迟或回声；在真机端到端
  测量通过前，不得称为可用的人声增强。

## 完成判据

1. 三首本地歌曲默认暂停，用户手动播放。
2. S3 每帧发送环境谱、模式、现实人声增益意图与置信度。
3. Mac 回报当前输出设备，S3 第二页显示 `AirPods Pro` 及真实路由状态。
4. Mac 对 `SONG_EQ` 产生真实可测的多段 EQ；安静时恢复平直。
5. `EXTERNAL_VOICE_INTENT` 单独测端到端延迟、可懂度和回声，失败也算有效结论。
6. UI 始终区分“决策已产生”“Mac 已执行”“AirPods 已播放”。
